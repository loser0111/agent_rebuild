# 10 · 前端 Markdown 渲染

> 目标：模型回答以 Markdown 正确呈现，覆盖对话场景的常见语法，同时保证流式渲染不闪烁、链接不成为 XSS 入口。

---

## 1. 为什么自研而不引 react-markdown

| 维度 | 自研（当前） | react-markdown + 插件链 |
| --- | --- | --- |
| 体积 | 0 依赖（gzip 后逻辑约 4KB） | +80KB 左右依赖链 |
| 流式控制 | 完全可控（见 §4） | 需绕开库的解析流程 |
| 版本风险 | 无 | 主版本升级可能破坏 API |
| 安全性 | 全 React 元素，无 innerHTML | 需额外配 rehype-sanitize |

**关键约束**：流式渲染时文本是不完整的（例如刚好输出到 `**粗`），第三方库会把未闭合标记原样显示成字面量。自研才能做「隐藏末尾未闭合标记」。

## 3. 安全：链接协议白名单

模型可能输出：

```markdown
[点我](javascript:alert(document.cookie))
```

直接渲染成 `<a href>` 就是一个**可点击的 XSS**（虽然 React 会警告，但不会阻止）。

因此所有链接都过一遍白名单：

```ts
export function isSafeHref(href: string): boolean {
  const h = href.trim().toLowerCase()
  if (h.startsWith('http://') || h.startsWith('https://')) return true
  if (h.startsWith('mailto:')) return true
  if (h.startsWith('/') || h.startsWith('#') || h.startsWith('./') || h.startsWith('../')) return true
  // 无协议的相对路径
  return !/^[a-z][a-z0-9+.-]*:/.test(h)
}
```

不在白名单的链接渲染为**不可点击的删除线文本**（带 title 提示），而不是丢掉内容。

外链统一加 `rel="noreferrer noopener"`。

## 4. 流式渲染的鲁棒性

这是自研的核心价值。三个具体问题与解法：

### 4.1 未闭合的行内标记

模型逐字输出 `收到你的消息：**测试**` 时，中间会经历：

```
收到你的消息：*
收到你的消息：**测
收到你的消息：**测试
```

若直接渲染，用户会看到孤立的 `*` 一闪而过。

**解法**：`parseInline(src, trailing)` 在流式模式下剥离末尾未闭合的标记字符：

```ts
function stripTrailingMarker(inlines: Inline[]): Inline[] {
  const last = copy[copy.length - 1]
  if (!last || last.kind !== 'text') return copy
  const stripped = last.text.replace(/[`*_~[\]]+$/, '')
  // ...
}
```

### 4.2 未闭合的代码围栏

流式中途 ```` ```go ```` 还没有结束标记。若按"未闭合就不当代码块"处理，用户会看到原始的三反引号。

**解法**：`parseBlocks` 允许围栏未闭合，标记 `closed: false`，仍然渲染为代码块（只是隐藏复制按钮）。

### 4.3 只有最后一块是"正在输入"

```tsx
const isLast = i === blocks.length - 1
const trailing = streaming && isLast
```

只有最后一块需要剥离未闭合标记，前面的块已完整，正常解析。

## 5. 手写解析最容易出错的地方

### 5.1 表格误判

不能只看"含 `|`"，必须下一行是分隔行：

```ts
if (line.includes('|') && isTableSeparator(lines[i + 1])) { ... }
```

否则 `a | b` 这种正文会被当成表格。

### 5.2 嵌套列表

判据是**缩进**，不是列表符号：

```
- 一级
  - 二级      ← 缩进 > 上级，属于子列表
- 另一个一级  ← 缩进回到基础，同级
```

实现上递归解析，`parseList` 返回 `{ items, next }` 让上层知道消费到哪一行。

还有两个边界：
- 缩进**小于**基础缩进 → 属于外层列表，结束当前解析
- 同级但类型不同（有序 ↔ 无序）→ 是两个独立列表

### 5.3 表格单元格内的转义管道

`| a \| b | c |` 应解析为 3 个单元格还是 2 个？正确答案是 2 个（`a | b` 和 `c`）。需要逐字符扫描而非简单 `split('|')`。

## 6. CSS 要点

| 类 | 作用 |
| --- | --- |
| `.md-table-wrap` | `overflow-x: auto`，宽表格横向滚动不撑破布局 |

| `.md-list .md-list` | 嵌套列表缩小间距（否则深层级太松散） |

| `.md-unsafe-link` | 不安全链接的删除线样式 |
| `.md-p br` | `display: block` 让段内换行真正换行（`white-space: pre-wrap` 下的补充） |

## 8. 已知限制

| 限制 | 说明 |
| --- | --- |
| 不支持 HTML 内联 | 模型输出 `<div>` 会作为文本显示。这是**刻意的**安全选择 |
| 不支持脚注/目录 | 对话场景极少用 |
| 图片不加载 | 降级为链接（图片源不可控，且会泄漏 referer） |
| 嵌套列表固定按无序渲染子级 | `parseList` 递归时子级有序性未完整传递（子项混合有序/无序时表现简化） |
| 表格不支持多行单元格 | 单元格内换行需用 `<br>`，当前按单行处理 |

如果需要，以上都可以继续补。
